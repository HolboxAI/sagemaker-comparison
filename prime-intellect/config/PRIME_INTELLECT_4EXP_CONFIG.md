# Prime Intellect — 4-experiment config (Fireworks parity)

This is the Prime Intellect leg of the three-platform benchmark. It reproduces the
same four experiments as [`fireworks/config/FIREWORKS_4EXP_CONFIG.md`](../../fireworks/config/FIREWORKS_4EXP_CONFIG.md)
and [`sagemaker/config/SAGEMAKER_4EXP_CONFIG.md`](../../sagemaker/config/SAGEMAKER_4EXP_CONFIG.md),
on **Prime Intellect** — but on the *on-demand pod* surface (self-run `prime-rl`
via CLI + SSH), **not** the hosted "training runs/jobs" surface.

The pod image ships **prime-rl 0.7.0** (`/app`, venv at `/app/.venv`), which is
older than GitHub `main` — see §8 for the version-drift findings.

## 8. Findings (platform-specific)

### 8.1 VLM SFT is blocked by version drift (the headline)

`prime-rl 0.7.0` (pod image) **rejects** `[model.vlm]` for SFT:

```
validate_renderer_vs_vlm: "renderer-only SFT does not support VLMs yet.
The renderer tokenizes text-only message dicts client-side and cannot handle image inputs."
```

GitHub `main` has **removed** this check and supports VLM SFT (its remaining
constraint is only `freeze_vision_encoder=false` being incompatible with LoRA). So
ORena SFT is blocked by the *pod image version*, not by the platform itself.

**This is the mirror of Fireworks' gap:** Fireworks cannot RL `qwen3p5-9b`; Prime
Intellect 0.7.0 cannot SFT a VLM but *can* RL one (the RL config carries `vlm` at
`rl.py:109` and rolls out through vLLM, which handles images natively).

### 8.2 GRPO has no KL term

`GRPOAlgoConfig` on 0.7.0 has no `kl_beta` (only an optional `length_penalty`).
The reference's KL beta 0.04 has no equivalent knob — recorded as a divergence.

### 8.3 Qwen3 thinking-mode is the dominant RL footgun

With `enable_thinking=true` (the renderer default), every completion runs to
`max_completion_length` and rewards collapse to 0 (Truncation 100%). Setting
`[orchestrator.renderer] name="qwen3" enable_thinking=false` dropped truncation to
~0-3%. SageMaker hit the same issue and did not disable it (its reward stayed 0).

### 8.4 zero-advantage filter aborts a fresh-model GRPO run

GRPO's `post_batch_filters` default to `zero_advantage enforce=true`, which drops
every group whose rollouts share a reward (the common case for a fresh model) and
aborts with `10 consecutive empty train batches`. Overriding it to `enforce=false`
lets training proceed.

### 8.5 LoRA adapter is silently stripped at checkpoint (default)

With `save_adapter_separately=false` (default), the saved `model.safetensors` is the
*un-fine-tuned base* — a naive eval scores micro-F1 ≈ 0.02. Set
`save_adapter_separately=true` and merge at eval.

### 8.6 Single-GPU RL requires a CUDA_VISIBLE_DEVICES hack + a vLLM memory cap

The single-node RL launcher wants disjoint GPU ids for inference vs trainer. On a
single GPU, `CUDA_VISIBLE_DEVICES="0,0"` satisfies the count check (both map to
physical GPU 0). vLLM's default `gpu_memory_utilization=0.9` then fails because the
trainer already holds ~3.8 GiB; set `[inference] gpu_memory_utilization=0.6` and
`[inference.model] max_model_len=512`.
